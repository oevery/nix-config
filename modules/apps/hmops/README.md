# hmops 控制台

**任务优先动效样片（不联网）：** 在本目录运行 `cargo run --locked --example task_console`。用 ↓ 选中 Mihomo，Enter 进入网络路径，再按 Enter 模拟出口回执；`r` 重播，`q` 退出。样片使用固定演示数据，不读取主机清单，不执行任何模块命令，不改变正式 `hmops tui`。

在主机声明中选 `apps/hmops`，激活后运行 `hmops tui`，不要加 `sudo`。「总览 / 维护 / 服务 / 日志」切换内容区，短下划线表示当前栏目。顶栏反色表示键盘焦点，纵向列表用 `➤` 标出当前可打开的项目。维护列表右侧说明打开后会发生什么。点击「搜索」或按 `/` 打开全局搜索浮层（例如搜「日常更新」「日志」「锁文件」），`Esc` 关闭并回到原处。日志正文里的 `/` 只筛选当前日志。配置仓库有改动时可查看工作区状态摘要，不局限于锁文件。计划、搜索和导航不会隐式执行更新；更改服务或配置时单独确认。

顶栏在各页保持同一位置。模块或阅读器中按 Tab 进入顶栏，左右选择、Enter 打开；Tab 或 Esc 回到内容。输入、确认或执行任务时不允许用顶栏跳走。

从「维护 → 预览主机更新」查看本机的更新范围、步骤和 Nix 存储余量，打开计划不会执行更新。104 列起步骤与操作并排，窄屏上下排列。执行中途停止时，每一步保留完成、失败或未执行状态，可选「查看本次执行记录」读完整原因。

首页本地优先显示产品名，SSH 优先显示主机名。80–103 列保留紧凑身份区，104 列起使用四行身份信息并显示交换空间与平均负载（1、5、15 分钟）。普通模式达到 33 行时，四行信息从首行排满，徽标在左侧十列内等比居中；字符徽标也用四行。CPU 总占用与最忙的两个核心使用同一百分比刻度；普通模式达到 28 行后显示四个核心。可识别的 Apple 性能核和能效核分组显示，否则使用逻辑核数。CPU、内存及存储占用率低于 70%、达到 70%、达到 90% 分别用绿、黄、红色；内存可用条固定绿色。占用比例不是压力告警。

青绿色用于字标、系统徽标、标题与导航强调。各栏目固定显示完整 HMOPS 图形字标，无图形时原位显示粗体文字。仪表用薄荷绿作基础色，不改变占用率的黄红阈值。

存储显示已用百分比及已用/总量。读写速率需要同一设备两次有效计数：macOS 按挂载设备匹配 APFS 卷统计，Linux 读取挂载设备的块统计；无法归属时隐藏。网络上下行各用一行薄荷绿柱状图，右端是最近读数，两行共用时间窗与 1/2/5 分档量程。缺少样本和零速率都画同色连续底线，前者的读数为 `—`。地址取自所示接口，不是公网出口。

资源在首页后台约每三秒采一次。macOS 内存可用量是空闲页加非活跃页，Linux 使用系统可用量；已用按同一口径从总量扣除。容量使用 IEC 单位，网速使用十进制 B/s、kB/s、MB/s。网络仅统计所示默认路由接口的收发计数，不主动测速，不证明代理出口；需要两次连续读数才显示速率，切换接口或计数重置时重新采样。磁盘可用量按普通用户口径（macOS 优先数据卷）。

「生效配置」只在运行目标与 profile 一致时显示 `#代号 · 短哈希 · 提交标题`。构建时由 Git flake 写入完整哈希及脏标记；脏构建的标题对应其基准提交，不包含未提交改动。标题从本地仓库按该哈希读取，不取当前 HEAD。旧代或无 Git 来源的构建显示「未记录来源提交」；本机没有对应提交时保留哈希、提示「标题不可用」。

**服务：** 列表只显示本机声明的服务。Mihomo 单页使用同一 Nix 构建中的控制器；打开和 `r` 刷新只查询状态，不读取私有订阅表。104 列起状态与操作并排，窄屏折叠服务控制。失败、停止、未安装及未知分别显示；不能读取当前订阅不等于未选择。

**订阅：** 「更新当前配置」刷新已选订阅。「管理订阅」经确认后交由终端授权并读取名称和 ID，旧单源可能在此时迁移。`a` 登记新名称与隐藏输入的地址，不下载或切换；`Enter` 确认后应用所选 ID，成功才切换；`d` 只能移除非当前项。服务控制中的重载仅发送信号，不等同于下载、切换或确认配置已加载。

**验证网络出口：** 在全局搜索输入「出口」或「诊断」。配置中声明的 TUN 名仅作预填，可修改；`Esc` 取消，不发请求，`Enter` 才通过所选接口探测。结果仅在诊断页展示，不代表所有代理规则可用。

**日志：** 全局「日志」只列本机配置的来源；移动选项不读取日志，`Enter` 才开始跟随。从 Mihomo 的「查看日志」可直接打开同一个阅读器。默认通过 `mihomoctl logs -n 100 -f` 跟随服务日志，`l` 切换到内核实时流（无历史）或返回。未激活新版服务时可能尚无合并日志；不拼接旧分流文件。`/` 筛选、空格暂停或恢复、方向键翻阅。没有记录、没有匹配和权限受限分别提示，不自动提权。退出筛选输入后，`Esc` 关闭本次跟随并恢复原页和原焦点；经搜索打开也一样。内存保留最近 256 行，每行最多 2048 字节。

**显示：** 保留终端背景。首次打开时，点阵在约 600 毫秒内依次显出顶栏、主机、资源、配置和底栏；SSH 默认缩短整页入场，`--motion off` 直接显示最终态。首次按键跳过入场并立即生效，返回总览不重播。直连终端启动时只查询一次 Kitty 图形能力，收到本次成功回执才原位放置透明徽标。无响应、SSH、tmux、screen 和 `NO_COLOR` 环境沿用独立字符画，不依赖专用字体。低于 80×24 不进入全屏，运行中缩小时不接受操作确认。更新预览另行显示 `/nix/store` 所在卷可用空间与已用比例，不代表构建进度。

| 命令 | 行为 |
| --- | --- |
| `hmops modules --json` | 声明的服务和执行引擎，不代表服务在线 |
| `hmops status --json` | 查询已知服务；未知值或模块错误不等于已停止，出口不会自动探测 |
| `hmops check` | 运行现有 `hc`，不激活 |
| `hmops sync` | 要求干净工作区，快进同步并按已有锁文件切换 |
| `hmops update` | 同步后运行 `flu`、`hms` 或 `drs`，再 `mise upgrade --global` |
| `hmops update --all` | 另外执行 macOS 软件更新或 Debian apt 更新／升级 |

Agent 可在更新命令末尾加 `--json`：不请求人工认证，结果包含已完成阶段，失败时还包括 `STEP_FAILED`、失败阶段、未执行阶段和非零退出码。`hmops update --plan --json` 只返回计划。

更新前用 `hmops update --all --plan` 查看顺序。仓库位置与 `hc`、`flu` 相同，为 `~/.config/home-manager`。更新只在上一步成功后继续，不自动 stash、reset、提交、推送或回滚。`flu` 会留下未提交的锁文件差异，未处理前下一次同步会拒绝运行。`drs` 可能升级或清理 Homebrew；Linux 激活可能更新 runner 和网关。确保空闲再切换。`update --all` 不会额外刷新 Mihomo 订阅。系统操作交回原命令处理认证，Agent 可显式使用 `--non-interactive`；没有权限或外部工具需要额外输入时不应视为成功。SSH 断开不保证任务继续，长操作请使用已有的持久终端会话。

**模块操作：**

- **Mihomo**：订阅、服务控制和平台日志由配套 `mihomoctl` 管理，详见 [安装及管理](../mihomo/README.md)。
- **Multica**：区分服务状态、日志和执行环境。OMP 版本只证明 CLI 可调用，不能代替实际派单。见 [runner 说明](../multica/README.md)。
- **Magpie**：分别检查用户服务和网关健康，管理页入口不显示密钥，不读取或导出服务环境。见 [网关说明](../magpie/README.md)。

**开发预览：** 本目录执行 `cargo build --locked`。在临时 `$XDG_CONFIG_HOME/hmops/host.json` 写入 `{"name":"preview","system":"aarch64-darwin","modules":["apps/mihomo"]}`（平台按本机替换），使用该环境启动 `target/debug/hmops tui`。要取得实际状态和回执，`PATH` 需包含本仓库对应版本的 `mihomoctl`。清单只控制展示，不隔离真实操作；只预览时可进入设备名输入后按 Esc，不必发请求或更改服务。
