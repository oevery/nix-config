# Change: hmops-nightflight

## Proposal
以独立 `apps/hmops` 提供普通用户主机运维工作台，按主机发现实际启用的模块，统一 CLI、中文键盘界面和失败反馈。不激活主机、不发布二进制；订阅、配置和服务由配套控制器执行。

## Spec
### ADDED
- Requirement: 同步保留锁文件；日常更新显式刷新输入并更新全局 mise 工具；仅完整更新包含宿主系统。脏工作区、无法快进和步骤失败时停止，不自动修复或提交。
- Requirement: Mihomo 提供多订阅登记、按 ID 切换、更新当前配置及按需网络诊断；Multica runner、Magpie 网关各管各自的状态；不把“服务运行”当作端到端成功。
- Requirement: Linux TUN 系统服务由管理员独立接入，Darwin 保留 LaunchDaemon；状态查询不借用管理员权限。完整配置归 root、权限 `0644`，订阅源归 root、权限 `0600`；敏感值不进 Nix store、日志或参数。
### Acceptance
#### Scenario: 首次打开主机总览
- GIVEN 普通用户在至少 80×24 的终端启动控制台
- WHEN 首页打开或在入场期间按 `/`
- THEN 整页从粒子揭示至最终布局，正文和底栏不提前露出，无独立启动页；首键即时生效。同一固定字符格位置支持图形和字符徽标。更小窗口在进入备用屏幕前提示退出。
#### Scenario: 在线路尚未验证时查看主页
- GIVEN 已选入 Mihomo 模块但尚未执行探测
- WHEN 打开 TUI 或查询 JSON
- THEN 区分已配置、运行状态与出口证据；不自动联网、提权或修改状态。
#### Scenario: 主机监测与全局导航
- GIVEN 普通用户在宽屏或 80×24 窗口打开总览
- WHEN 切换栏目、进入二级页或打开全局搜索
- THEN 80–103 列采用紧凑读数，104 列起展示更多上下文；两档均保留主机身份、CPU／内存／存储／网络四格、配置状态和查看更改。无 CPU 大趋势、无主动网络探测；其他页面与切页动效保持不变。
- 普通模式身份区四行，苹果图形使用透明 256×256 PNG。品牌、系统徽标、区块标题和导航强调用青绿色；图形首页绘制完整 HMOPS 字标，无图形时原位显示粗体 HMOPS，不改变行高或占用条厚度。图表基础色为薄荷绿；CPU、内存、存储占用率 70% 起黄、90% 起红，可用条始终薄荷绿。存储同时给出百分比、已用/总量；只展示同一卷或设备可核对的读写速率。网络显示本机地址和采样接口，上下行共用分档量程；柱和底线均用薄荷绿，未采样与零值以读数区分。
- 首页达到 33 行高时，顶栏下划线、身份区、两排仪表、配置状态之间各留两行空白。普通宽度的身份区为 10 列徽标加四行左对齐文字，从首行起笔；权限与首行齐平。图形等比居中于 8×4 内框，字符回退也用四行；24 行窗口沿用原紧凑布局。
- 「生效配置」仅关联实际运行的代：`#编号 · 短哈希 · 提交标题`。构建用 flake 的完整 `rev` 或 `dirtyRev` 留存来源；标题按该对象在本地解析，脏构建标明「含未提交改动」。长标题才截断；无来源的旧代提示「未记录来源提交」，不借用当前 HEAD。
- 总览、维护、服务、日志共享字标和顶栏；详情保留所属栏目的青绿色短下划线，顶栏键盘焦点用终端反色。「搜索」「查看更改」使用紧凑按钮，不缩小点击区域。正文与搜索列表只在接收输入时用青绿色 `➤` 标记当前项。维护入口采用名称与说明两列，未选行使用默认前景色，选中行两列同色、仅名称加粗；空间不足时在列表下方显示当前项说明。全局搜索为模态浮层，Esc 回到原页面及焦点；日志正文内的 `/` 筛选当前阅读器。
#### Scenario: 从服务列表管理 Mihomo
- GIVEN 普通用户进入服务栏目，以名称、只读状态与用途浏览本机声明的模块，未知不当作停止。
- WHEN 打开单页详情，只读新版状态；控制器不读私有订阅表或旧来源，没有公开摘要就显示「需授权查看」，不探测、不提权。详情与搜索共用服务操作判断：状态未知或过渡中不提供启停操作。无子页签及常驻出口区域。104 列起状态与操作并排，紧凑模式只折叠服务控制。
- THEN 主动管理并确认后才读取订阅列表；添加不应用，切换成功才显示新当前项，失败保留控制器实际选择，不能移除当前项。服务日志和可选内核实时流均通过配套控制器；出口验证保留为搜索入口。
#### Scenario: 主机更新部分失败
- 打开维护计划只预览目标主机、更新范围、Nix 存储余量和真实步骤。80–103 列纵向排列，104 列起左侧显示步骤，右侧显示余量与操作。浏览和取消确认都不执行更新。
- GIVEN 用户明确执行日常更新
- WHEN 任一步失败
- THEN 保留已执行步骤和原始工作区，不执行后续阶段，提供非零状态和诊断。
- 原位标明已完成、失败及未执行的步骤；失败后可打开执行记录阅读完整原因。
#### Scenario: 找到日志而不必记住平台命令
- 全局「日志」只列本机已配置且有日志入口的来源，按名称和说明两列显示；移动焦点不启动跟随。Mihomo 的「查看日志」跳过来源列表。宽窄屏共用无侧栏的阅读器，默认不占用空筛选或诊断行；区别无权读取、暂无记录及筛选无匹配。
- GIVEN 普通用户在首页或服务页
- WHEN 用 `/` 搜「日志」并选择本机模块
- THEN 面包屑由打开阅读器的页面决定，不由日志源决定；直接打开或经搜索打开，Esc 均关闭本次跟随并恢复原页和原焦点。暂停冻结当前正文，即使跟随已结束也只更新状态；主动恢复后显示缓冲的记录，不重启跟随。可以按关键词筛选；读权限不足时不隐式提权。

## Design
Rust/Ratatui 应用与 Nix 用户模块同目录。主机清单来自 Nix；平台服务和特权归模块。CLI/TUI 共用更新执行计划，保留现有短命令。普通用户浏览，特权动作交回终端。

应用名称为「控制台」。各页共用顶栏；首页为身份、四格读数与配置状态。本地产品名优先，SSH 主机名优先。内存成对显示已用、可用；网络标明采样接口，CPU 与速率等有效区间。图形与独立设计的字符徽标同槽；直连 Rex 等终端以图形协议回执决定是否放图，不按品牌推断。用平台只读接口采集，不调用 fastfetch。顶部搜索支持点击和 `/`，阅读器中 `/` 保留筛选语义。首次启动对首页最终帧做整页粒子归位，SSH 默认精简，不增加切页消融。Mihomo 单页与订阅浮层共用配套控制器；跨服务日志阅读器按需启动、离开停止。只对实际请求显示回执。

独立样片保留为无副作用的动效对照，不接真实模块。
